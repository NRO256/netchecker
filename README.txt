1. はじめに（概要と開発コンセプト）
================================================================================

「突然インターネットに繋がらなくなった」
「メールは受信できるのに、Webサイトが開かない」
「Wi-Fiマークは付いているのに、通信エラーになる」

ネットワークの接続障害が発生したとき、その原因が「PC本体」「LANケーブル・Wi-Fi親機」「宅内ルーター」「光回線・プロバイダ（ISP）」「DNSサーバー」「Webサーバーやプロキシ」のどこにあるのかを切り分けるのは、一般ユーザーはもちろん、IT担当者にとっても手間と知識を要する作業でした。

従来の調査方法では、コマンドプロンプトを開いて ipconfig、ping、nslookup、curl などのコマンドを順番に手動で打ち込み、結果を1つずつ読み解く必要がありました。また、市販の診断ツールはインストーラーの実行や管理者権限を要求されることが多く、トラブルが発生しているPCに手軽に導入できないという課題がありました。

本ソフトウェア「NetChecker Portable」は、これらの問題を解決するために開発された、Windows専用の完全ポータブルなネットワーク階層診断ツールです。

マウスでダブルクリックするだけで、PC内部からインターネットの出口までを5段階のレイヤーで自動テスト。わずか数秒で障害の発生箇所を特定し、専門用語を噛み砕いた「総合判定」と「具体的な対処アドバイス」を画面に表示します。さらに、調査結果を自動でテキストファイルに保存するため、サポート窓口への報告資料としてもそのまま活用できます。

2. 主な特長
================================================================================

◆ 超軽量・インストール不要（ノーレジストリ）
   単一の実行ファイル（NetChecker.exe、約181KB / 184,832バイト）のみで完結。追加ライブラリ（.NET Framework、Visual C++ 再頒布可能パッケージ等）のインストールは一切不要です。レジストリやシステム設定の変更も行わないため、PCを汚さず、USBメモリから直接起動できます。

◆ 外部依存クレートゼロ（完全ネイティブ実装）
   最新のRust 2024 Editionで記述され、サードパーティ製の外部ライブラリを一切排除。Windows標準のWin32 API（IP Helper API、ICMP API、WinINet API）を直接呼び出すネイティブバイナリとして構築されています。無駄なオーバーヘッドがなく、極めて高い堅牢性と高速動作を実現しています。

◆ 5段階の階層的障害切り分け
   障害の発生ポイントを「PC本体」「ルーター」「回線出口」「DNS名前解決」「Web通信」の5レイヤーに論理分解して順次検証。どこまで通信が到達しており、どこで遮断されたのかを明確に可視化します。

◆ 誤判定を防ぐ冗長化フォールバック機能
   インターネット疎通、名前解決、Webアクセスの各テストでは、主系（Google）が応答しない場合に自動で副系（Cloudflare）へフォールバックして再検証を行います。相手先サーバーの一時的な障害による誤検知を自動で防止します。

◆ 現実の運用を考慮した柔軟な正常判定
   セキュリティ対策として外部からのPing（ICMP）応答を拒否しているルーターや、社内ファイアウォールでPing通信が遮断されている企業内LAN環境でも、Webアクセスや名前解決が正常に通っていれば「正常 (ルーターPing応答なし)」「正常 (ICMP制限環境)」として正しく識別します。

◆ Win32 API詳細エラーコードの自動日本語解説
   通信に失敗した場合、単に「エラー」と表示するだけでなく、OSのWin32 APIが返したエラーコード（GetLastError()）と、その日本語解説（例: 12007 サーバー名解決失敗、12029 接続失敗など）を併記します。原因特定が大幅に迅速化されます。

◆ ダブルクリック実行と高度なCLI運用の両立
   普段はアイコンをダブルクリックするだけで誰でも直感的に使えます。一方で、コマンドライン引数（--target, --timeout, --json, --no-wait 等）やプロセス終了コード（Exit Code）にも完全対応しており、社内LAN監視スクリプトやバッチ処理への組み込みも容易です。

◆ UTF-8 BOM付きレポートの自動保存
   診断完了時、実行ファイルと同じフォルダにタイムスタンプ付きのレポートファイル（NetChecker_YYYYMMDD_HHMMSS.txt）を自動生成します。Windows標準のメモ帳やスクリーンリーダーで文字化けせずに直接開くことができます。

3. セキュリティ・プライバシーと安全性（安心してご利用いただくために）
================================================================================

NetChecker Portableは、個人の大切なPCはもちろん、企業の重要端末や教育機関・官公庁の環境でも安心して実行できるよう、厳格なセキュリティポリシーに基づいて設計されています。

3.1 完全ローカル動作（外部通信・テレメトリゼロ）
--------------------------------------------------------------------------------
本ソフトウェアには、ユーザーの個人情報収集、PC内データのスキャン、使用状況ログの送信（テレメトリ）、広告表示、自動アップデート通信などの機能は一切含まれていません。
診断時に行われる通信は、ユーザーが指定した（または既定の標準的な）接続先に対するPing疎通確認、DNS名前解決、Webページ到達性確認のみです。完全オフライン環境であっても、PC内部や宅内機器までの診断が正常に行えます。

3.2 管理者権限（UAC昇格）不要
--------------------------------------------------------------------------------
本ツールはWindows標準の一般ユーザー権限のみで動作します。
起動時に「ユーザーアカウント制御（UAC）」の警告ダイアログが表示されることはなく、管理者権限（Administrator）を持たない会社の支給PCや共有PCでも安全に実行できます。

3.3 PC設定やネットワーク構成の不改変（非侵襲設計）
--------------------------------------------------------------------------------
本ツールは純粋な「読み取り・診断」のみを行います。
Windowsのネットワーク設定、IPアドレス、DNS設定、プロキシ設定、ファイアウォール規則、レジストリなどを書き換えることは一切ありません。本ツールの実行によって既存のネットワーク構成が変更される心配はありません。

3.4 安全な保存先フォールバック機能
--------------------------------------------------------------------------------
USBメモリの物理書き込み禁止スイッチが入っている場合や、書き込み権限が制限されたフォルダで実行された場合でも、プログラムがクラッシュすることはありません。
以下の順序で書き込み可能な場所を自動探索してレポートを安全に保存します。
(1) 実行ファイルと同一のフォルダ
(2) 現在のカレントフォルダ
(3) システム一時フォルダ (%TEMP%)
(4) 現在のユーザーのデスクトップ
(5) ユーザーホームフォルダ (%USERPROFILE%)

3.5 Windows SmartScreen警告（青い画面）が表示された場合の対応
--------------------------------------------------------------------------------
インターネットからダウンロードした本ツールを初めて実行した際、Windowsによって「WindowsによってPCが保護されました」という青いダイアログ（SmartScreen）が表示されることがあります。

【理由】
本ソフトウェアは個人開発のオープンソースソフトウェア（OSS）であり、年間数十万円の維持費がかかる商用コード署名証明書を購入していないため、Windowsのダウンロード実績数が蓄積されるまでの間、OSが機械的に安全確認のダイアログを表示するセキュリティ仕様によるものです。ウイルスやマルウェアによる警告ではありません。

【起動手順】
1. 青いダイアログ画面内の「詳細情報」という下線付きテキストをクリックします。
2. 隠れていた「実行」ボタンが右下に現れますので、「実行」をクリックします。
3. これにより通常通りNetCheckerが起動します（次回以降はこの警告は表示されません）。

2. 黒いコンソール画面が立ち上がり、自動的に5段階のネットワーク接続診断が開始されます。

================================================================================
6. 診断項目の詳しい内容（5段階階層テストと冗長化フォールバック）
================================================================================

NetCheckerは、以下の5つのステップを通じて障害発生箇所を絞り込みます。

----------------------------------------------------------------------
[1/5] ネットワークアダプタ検証
----------------------------------------------------------------------
PCに搭載されている有線LANやWi-FiアダプタがOSに正常認識され、有効なIPv4アドレスを取得できているかを確認します。
- 物理NICのリンク速度（例: 1000Mbps, 866Mbps等）を自動計測して表示します。
- システムに設定されているIPv4 DNSサーバーアドレス一覧を表示します。
- 仮想NICやVPNアダプタが複数存在する場合でも、Windowsのルーティングテーブル（GetBestInterface）を解析し、外部宛先に対して実際に使用されている「主要アダプタ」を自動選択します。

----------------------------------------------------------------------
[2/5] 宅内ルーター (デフォルトゲートウェイ) 疎通
----------------------------------------------------------------------
PCが取得したデフォルトゲートウェイ（宅内のルーター）宛てにICMP Echo（Ping）を送信し、宅内LAN機器との通信可否と応答時間（RTT）を計測します。
※セキュリティのためPing応答を無効化している家庭用ルーターやメッシュWi-Fi親機の場合でも、後続のインターネット通信が成功していれば誤判定せず「正常 (ルーターPing応答なし)」として処理します。

----------------------------------------------------------------------
[3/5] インターネット出口疎通 (Ping)
----------------------------------------------------------------------
宅内ルーターを越えて、インターネット上の主要サーバーまでパケットが届いているかを確認します。
- 主系ターゲット: Google Public DNS (8.8.8.8)
- 冗長化フォールバック: 応答がない場合、自動的に副系ターゲット（Cloudflare DNS: 1.1.1.1）へPingを再試行します。
- カスタム指定時: 「-t」オプションで指定された対象ホストのIPv4アドレスへ送信します。

----------------------------------------------------------------------
[4/5] 名前解決 (DNS)
----------------------------------------------------------------------
ドメイン名（URLのホスト名）をIPアドレスに変換できるかを確認します。
- 主系ターゲット: www.google.com
- 冗長化フォールバック: 解決失敗時、自動的に副系ドメイン（cloudflare.com）で再試行します。
- これにより、「回線自体は繋がっているが、DNSサーバーのトラブルでWebサイトが開かない」という状態を即座に見破ります。

----------------------------------------------------------------------
[5/5] Webアクセス (HTTPS/WinINet)
----------------------------------------------------------------------
実際にHTTPS通信を行い、Webサーバーから正常なレスポンス（HTTP 200等）が返ってくるかを確認します。
- 主系URL: https://www.google.com
- 冗長化フォールバック: 接続失敗時、自動的に副系URL（https://www.cloudflare.com）へ再試行します。
- プロキシ自動検出: Windowsシステム（WinINet）および環境変数（HTTPS_PROXY等）に設定されたプロキシを自動検出し、プロキシ経由での通信成否を検証します。

----------------------------------------------------------------------
◆ Win32 API / ICMP エラーコード日本語解説機能
----------------------------------------------------------------------
通信に失敗した場合、OS内部で発生したエラーコードと、その日本語解説がレポートに明記されます。

【代表的なエラーコードと解説の例】
・エラーコード 12007: サーバー名解決失敗 (ERROR_INTERNET_NAME_NOT_RESOLVED)
  → DNSサーバーに問い合わせましたが、サーバーのIPアドレスが見つかりませんでした。
・エラーコード 12029: サーバー接続失敗 (ERROR_INTERNET_CANNOT_CONNECT)
  → サーバーとのソケット接続確立に失敗しました。ポート遮断やサーバー停止が考えられます。
・エラーコード 12002: 要求タイムアウト (ERROR_INTERNET_TIMEOUT)
  → 要求に対する応答が制限時間内に返りませんでした。回線の輻輳や遅延が疑われます。
・エラーコード 12045: 無効な認証機関 (ERROR_INTERNET_INVALID_CA)
  → HTTPS通信のサーバー証明書が信頼された認証機関によって発行されていません。
・エラーコード 12157: TLS/SSLハンドシェイク失敗 (ERROR_INTERNET_SECURITY_CHANNEL_ERROR)
  → HTTPS通信時の暗号化プロトコルや証明書検証でエラーが発生しました。

7. 診断結果（総合判定）の見方と原因別の具体的な対処手順
================================================================================

診断完了時、NetCheckerは5つの結果を論理的に組み合わせて【総合判定】と【対処アドバイス】を出力します。

----------------------------------------------------------------------
【正常】
----------------------------------------------------------------------
すべてのステップが成功しました。インターネット接続は極めて良好です。

----------------------------------------------------------------------
【正常 (ルーターPing応答なし)】
----------------------------------------------------------------------
インターネットへの通信は正常ですが、宅内ルーターがPing応答を拒否しています。
【対処】一部の家庭用・法人用ルーター（NEC AtermやYAMAHAなど）はセキュリティのため外部Pingに応答しない設定が標準です。インターネットは問題なく利用できますので、特別な対処は不要です。

----------------------------------------------------------------------
【正常 (ICMP制限環境)】
----------------------------------------------------------------------
Web閲覧や名前解決は正常ですが、途中のファイアウォールによってPing（ICMP）通信のみが遮断されています。
【対処】セキュリティの厳しい企業内LANや教育機関ネットワークでよく見られる状態です。業務やWeb利用には一切支障ありませんので、安心してご利用ください。

----------------------------------------------------------------------
【端末内部エラー】（ステップ1失敗）
----------------------------------------------------------------------
PCがネットワークアダプタを認識できていないか、IPアドレスを取得できていません。
【対処手順】
1. PCの有線LANケーブルがカチッと音がするまで奥まで挿さっているか確認してください。
2. ノートPCの場合、Wi-Fiスイッチや「機内モード」がオンになっていないか確認してください。
3. Windowsの「設定」->「ネットワークとインターネット」を開き、アダプタが有効になっているか確認してください。

----------------------------------------------------------------------
【宅内ネットワークエラー】（ステップ1成功、ステップ2〜5全滅）
----------------------------------------------------------------------
PCは起動していますが、宅内ルーターと全く通信ができていません。
【対処手順】
1. Wi-Fiの暗号化キー（パスワード）が正しく入力されているか確認してください。
2. 有線LANの場合、ルーター側のポートにケーブルが正しく接続されているか確認してください。
3. 宅内ルーターの電源を抜き、1分待ってから再度電源を入れ直して再起動してください。

----------------------------------------------------------------------
【回線・プロバイダ側エラー】（ステップ1・2成功、ステップ3〜5失敗）
----------------------------------------------------------------------
宅内ルーターまでは届いていますが、そこから外部のインターネットへ出られません。
【対処手順】
1. 光回線終端装置（ONU）やモデム（VDSLモデム等）の「光回線」「LINE」「WAN」ランプが緑色に点灯しているか確認してください（赤点滅や消灯の場合は回線断です）。
2. プロバイダ（ISP）の契約・認証設定（PPPoEやIPoE/v6プラス）が切れていないか確認してください。
3. ご利用のプロバイダや回線事業者（NTT等）で大規模な通信障害が発生していないか、スマートフォンのモバイル回線等で障害情報を確認してください。

----------------------------------------------------------------------
【名前解決エラー】（ステップ1〜3成功、ステップ4失敗）
----------------------------------------------------------------------
インターネット回線自体は繋がっていますが、Webサイトの住所変換（DNS）ができません。
【対処手順】
1. ステップ1に表示された「DNS」アドレスを確認してください。
2. ルーターのDNS中継機能がフリーズしている場合があります。ルーターを再起動してください。
3. 一時的な回避策として、WindowsのネットワークプロパティでパブリックDNS（Google: 8.8.8.8 や Cloudflare: 1.1.1.1）を手動設定してみてください。

----------------------------------------------------------------------
【Web通信遮断エラー】（ステップ1〜4成功、ステップ5失敗）
----------------------------------------------------------------------
IP通信や名前解決は通っていますが、HTTPSによるWebページの取得のみが弾かれています。
【対処手順】
1. PCに導入されているセキュリティ対策ソフト（ウイルス対策ソフト）のWeb保護機能やファイアウォールが通信を誤って遮断していないか確認してください。
2. ブラウザやWindowsに古いプロキシ（Proxy）サーバー設定が残っていないか、「設定」->「ネットワークとインターネット」->「プロキシ」を確認してください。
3. 社内ネットワークの場合、認証プロキシのパスワード更新期限が切れていないか確認してください。

8. コマンドライン（PowerShell / CMD）からの実行・オプション一覧
================================================================================

コマンドプロンプトやPowerShellから実行することで、より高度な診断や自動化機能を利用できます。

【基本書式】
NetChecker.exe [オプション]

8.1 コマンドライン引数一覧
--------------------------------------------------------------------------------
オプション              説明
--------------------------------------------------------------------------------
-h, --help, /?, /h      ヘルプメッセージ（コマンド一覧と使用例）を表示して終了します。
-v, --version, /v, /version
                        バージョン情報（例: NetChecker Portable v0.5.1）を表示して終了します。

-t, --target <対象>     診断対象をカスタム指定します（ホスト名、IPアドレス、またはURL）。
    --target=<対象>     既定のGoogle/Cloudflareではなく、社内イントラサーバーや特定拠点の
                        到達性をテストしたい場合に使用します。
                        （例: -t example.com / --target=https://intranet.local）

-w, --timeout <ミリ秒>  Ping疎通およびWebアクセスのタイムアウト時間をミリ秒単位で指定します。
    --timeout=<ミリ秒>  指定可能範囲: 100〜30000 ms（既定値: 2500 ms）。
                        低速な衛星回線やモバイル回線の検証、あるいは超高速な社内LANでの
                        シビアな遅延検出に有効です。

--json                  診断結果を標準出力にJSONフォーマットで出力します。
                        スクリプト連携、ZabbixやDatadog等の監視エージェント連携、jqコマンド
                        によるパースに最適です。（※自動的に --no-wait が適用されます）

--no-wait               診断完了後の「何かキーを押すと終了します」という入力待機をスキップし、
                        処理完了後即座にプロセスを終了します。
                        バッチファイルやタスクスケジューラからの定期実行に必須のオプションです。

--no-report             診断結果レポートファイル（NetChecker_*.txt）のディスク保存をスキップします。
                        ファイル出力を伴わずに画面表示やJSON出力のみを行いたい場合に指定します。
--------------------------------------------------------------------------------

8.2 プロセス終了コード（Exit Code）の仕様
--------------------------------------------------------------------------------
NetCheckerは、バッチスクリプトやCI/CDパイプラインでの自動判定を可能にするため、診断結果に応じた終了コードを返します。PowerShellの「$LASTEXITCODE」やコマンドプロンプトの「%ERRORLEVEL%」で判定できます。

・終了コード 0 : 正常終了
  インターネット接続が正常、またはルーターPing応答なし・ICMP制限環境などの通信可能状態。
・終了コード 1 : コマンドライン引数の指定誤り
  存在しないオプションや、範囲外のタイムアウト値などが渡された場合。
・終了コード 2 : ネットワーク異常検出
  端末内部エラー、宅内ネットワークエラー、回線エラー、名前解決エラー、Web遮断エラーなどの障害を検出した場合。

9. 実践的な活用シナリオ
================================================================================

9.1 サポート窓口・ヘルプデスクでの状況切り分け（レポート送付依頼）
--------------------------------------------------------------------------------
エンドユーザーから「ネットが繋がらない」と問い合わせがあった際、NetCheckerを実行してもらい、生成されたレポートテキスト（NetChecker_*.txt）をメールやチャットで送ってもらうだけで、瞬時に原因（Wi-Fi未接続なのか、ONU故障なのか、DNS設定不備なのか）を特定できます。ユーザーに難しいコマンド操作を強いる必要がなくなります。

9.2 社内イントラサーバー・特定VPN拠点の接続診断（--target オプション）
--------------------------------------------------------------------------------
本社のファイルサーバーやクラウドERPへの通信可否を個別診断できます。
【実行例】
.\NetChecker.exe -t https://erp.company.internal --timeout 3000

9.3 厳格なLAN・高速回線でのタイムアウト調整（--timeout オプション）
--------------------------------------------------------------------------------
データセンター内や専用線などの高速環境において、500ms以上の遅延を異常として検知したい場合、タイムアウトを短縮して厳格にテストできます。
【実行例】
.\NetChecker.exe -w 500

9.4 PowerShellや監視ツールでの自動定期監視（--json / --no-wait）
--------------------------------------------------------------------------------
PowerShellスクリプトから呼び出し、ネットワーク障害時に管理者へアラート通知する運用が可能です。

【PowerShell監視スクリプト例】
$jsonStr = & .\NetChecker.exe --json
$result = $jsonStr | ConvertFrom-Json
if (-not $result.success) {
    Write-Warning "ネットワーク異常を検知しました: $($result.overall_judgment.title)"
    Write-Warning "アドバイス: $($result.overall_judgment.advice)"
    # ここにメール送信やWebhook通知処理を記述
}

9.5 USBメモリからの出張トラブルシュート・現場保守
--------------------------------------------------------------------------------
USBメモリの中に「NetChecker.exe」を入れて携帯しておけば、訪問先のクライアントPCや現場の端末に挿してダブルクリックするだけで、即座にネットワーク健全性を診断できます。PCに一切の痕跡（レジストリや設定）を残さないため、厳格なセキュリティポリシーを持つ現場でも安心です。

10. トラブルシューティング（よくある質問 FAQ）
================================================================================

Q1: 初回起動時に「WindowsによってPCが保護されました」と青い画面が出る
--------------------------------------------------------------------------------
【回答】
Windows SmartScreenによる安全確認画面です。NetCheckerは個人開発のオープンソースソフトウェアであるため、OSが安全確認のために表示しています。
画面内の「詳細情報」をクリックし、現れた「実行」ボタンを押すことで通常通り起動できます（ウイルスではありませんのでご安心ください）。

Q2: 「ルーターPing応答なし」と判定されたが、ネットは使える
--------------------------------------------------------------------------------
【回答】
問題ありません。最近のブロードバンドルーターやWi-Fi機器の中には、セキュリティ強化のため外部からのPing（ICMP Echo）パケットに応答しない仕様の機器が多数存在します。Webアクセスや名前解決が成功していれば正常に通信できています。

Q3: 「正常 (ICMP制限環境)」と表示されたが問題ないか？
--------------------------------------------------------------------------------
【回答】
全く問題ありません。企業や大学などの組織内ネットワークでは、セキュリティ対策としてPing（ICMP通信）を一括で遮断しているケースが一般的です。Webサイトの閲覧や業務システムの利用には一切影響ありません。

Q4: プロキシ環境下の社内LANでも動作するか？
--------------------------------------------------------------------------------
【回答】
はい、動作します。NetCheckerはWindowsのシステムプロキシ設定（WinINet）および環境変数（HTTPS_PROXY等）を自動検出し、プロキシサーバーを経由してWebアクセステストを実行します。

Q5: 生成されたレポートテキストがメモ帳で文字化けしないか？
--------------------------------------------------------------------------------
【回答】
文字化けしません。保存されるレポートファイルは「UTF-8 BOM付き」で出力されます。Windows 10 / 11 の標準「メモ帳」は UTF-8 BOM および LF 改行に対応しているため、そのまま綺麗に閲覧できます。

Q6: セキュリティソフトに誤検知（ウイルス判定）される心配はないか？
--------------------------------------------------------------------------------
【回答】
NetCheckerは外部の不審なライブラリを含まず、純粋なRust標準機能と正規のWindows APIのみを用いてコンパイルされています。また、パッカー（UPX等）による不透明な圧縮も行っていません。大半のセキュリティソフトでクリーンと判定されます。万が一誤検知された場合は、本ソフトウェアがオープンソース（ソースコード公開中）であることをご確認の上、セキュリティソフトの除外設定を行ってください。

11. ソースコードのビルド方法（開発者向け）
================================================================================

NetCheckerは、高信頼・高速・メモリ安全なプログラミング言語「Rust」で記述されています。ご自身でソースコードからバイナリをビルドしたい場合は、以下の手順に従ってください。

【必要環境】
- Windows 10 / 11 (64bit)
- Rust 1.85 以降 (Edition 2024 対応ツールチェーン)
- MSVC Build Tools (C++ ビルドツール / link.exe)

【ビルド手順】
1. リポジトリをクローンまたはダウンロードします。
2. プロジェクトのルートディレクトリで以下のコマンドを実行します。
   cargo build --release

3. 「target\release\NetChecker.exe」に最適化された単一実行ファイルが生成されます。
   （Cargo.toml内の最適化設定により、不要シンボルのストリップおよびLTOが適用され、
   最小サイズに圧縮されます）

【テストの実行】
単体テストを実行して各モジュールの正常性を検証できます。
cargo test
